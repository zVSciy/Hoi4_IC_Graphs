# `library`: every campaign, saved

The game library keeps every loaded or live-monitored output file, already parsed, in a SQLite database
(`library.sqlite3` in the app data folder). Old campaigns open instantly and can be compared without the original
`output.txt`.

| --- | --- |

## A game is identified by its content

The key idea is in <Src file="src/library/mod.rs" line={365}>Library::save_file</Src>. A game is identified by a 128-bit
xxHash <Src file="src/library/mod.rs" line={609}>fingerprint</Src> of the file's bytes, not by its path:

- saving an identical file changes nothing (`Unchanged`);
- saving a file that **extends** a stored game, meaning the same campaign played further (`output.txt` only ever grows),
  updates that game in place (`Updated`);
- anything else becomes a new game (`Added`).

See <Src file="src/library/mod.rs" line={174}>SaveOutcome</Src>. To detect "extends", `save_file` looks up games from the
same path and checks, while the file is being parsed, whether a stored game's fingerprint matches a prefix of the new
file. That uses `data::load_file_with`, so hashing and parsing happen in one pass over the memory-mapped file.

<Note title="Concurrency">
The duplicate check and the write happen inside one `IMMEDIATE` SQLite transaction, so saves from other threads (the live
monitor) or a second app instance cannot slip in between.
</Note>

## The codec

<Src file="src/library/codec.rs">codec.rs</Src> stores a `Dataset` as one zstd-compressed blob:

```text
magic "HOI4DS\0" + format byte
u32 dates, u32 tags, u32 metrics
u64 lines, u64 valid
i32 × dates     first date, then day-to-day deltas (almost all 1)
u64 × tags      packed country tags
f64 × metrics × tags × dates, byte-planar
```

Before compression, every value is XORed with the same country's value on the previous day, so unchanged days become
zero, and the bytes are split into eight planes so that similar sign and exponent bytes end up next to each other. Both
steps are exactly reversible: <Src file="src/library/codec.rs" line={103}>decode</Src> is bit-identical to what
<Src file="src/library/codec.rs" line={53}>encode</Src> received, and zstd shrinks a typical campaign several times over.
